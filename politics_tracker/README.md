# 考研政治刷题统计 · 详细使用指南

项目介绍、功能概览与快速开始见 [仓库首页](../README.md)。本文说明录入规则、历史数据导入、报表及备份恢复。

程序完全本地运行。原始操作保存在 SQLite 的 `events` 表；Session、错题池和当前状态可随时从事件重算。截图只作为附件，不参与统计。下文的数据文件路径均相对于 `politics_tracker` 目录。

## Windows 启动

需要 Python 3.11 或更高版本。直接双击仓库根目录的 `启动刷题统计.bat`。启动器会打开浏览器；首次启动若系统尚无 Streamlit，会在 `politics_tracker` 目录建立 `.venv` 并安装依赖。关闭服务可双击仓库根目录的 `关闭刷题统计.bat`。本目录内也提供对应的 `start.bat` 和 `stop.bat`。

如需从命令行启动，在 `politics_tracker` 目录打开 PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

如果安装的是其他受支持的 Python 版本，请相应调整 `py -3.11`。启动后访问 [http://localhost:8501](http://localhost:8501)。程序不需要联网服务或账号；首次安装依赖时需要网络。

## 导入已有数据

`seed_initial.py` 用于导入本项目预设的历史汇总，不是通用数据导入器。新用户可直接从空数据库开始录入，无需运行该脚本。如需使用这份历史汇总，**仅在首次录入任何记录之前**，在本目录运行一次：

```powershell
.\.venv\Scripts\python.exe seed_initial.py
```

导入 A0：单选 68 题、错 18；多选 58 题、错 32。导入 A1：单选作答 14、正确 11、再错 3；多选作答 2、正确 2。导入后 A1 池为 4/30、A2 池为 3/0，App 错题本为 7/30。原始刷题日期没有提供，因此事件按导入当天存档，并明确标记“历史汇总导入，实际刷题日期未知”。可用 `--date YYYY-MM-DD` 指定存档日期。

程序不会自动导入样例，避免覆盖你自己的新数据库。如果已有事件，导入脚本会拒绝再次运行。

## 使用规则

- 每条记录必须且只能选择一个大章节（马原、毛中特、新思想、史纲、思修）和一个阶段；刷新题和复刷错题分开记录。五个章节各自维护累计进度、App错题本快照、六个错题池和二刷基准。
- A0/B0 默认使用“本次新增”模式：只填这一轮新增的单选、多选题数，以及刷后的 App 错题本单选、多选数。程序自动加上数据库中的上次累计值，并在保存前显示换算后的累计数。
- 如果手头有 App 当前累计完成数，也可切换到“当前累计”模式直接填写。两种方式计算出的统计结果相同；事件日志会保留所选录入方式和原始输入。
- A1/A2/B1/B2 填刷后错题本数和本轮再错数。实际作答 = 刷前错题本 − 刷后错题本 + 再错。
- AX/BX 只维护 3+ 顽固错题余额，不进入六轨正确率。
- 开始二刷前，在“导出与维护”中选择维护章节并建立该章节二刷基准。B0 此后以该章节基准作差；其他章节可以继续一刷。
- 开始二刷后如有遗留一刷错题，仍可单独记录 A1/A2/AX；A0 新题则停止录入。
- 输入数无法与错题池核对时，程序拒绝保存并显示差值。历史记录不能直接编辑，只能撤销最近一次操作，然后重录。

## 章节迁移与结构化导入

首次启动新版时，旧数据库会在 `backups/politics_pre_chapters_*.db` 留下迁移前备份。全部原始历史事件及 Session 默认归入“马原”（包括旧的自由文本章节），原有备注、截图、日期、计算结果保留；迁移失败会回滚，重复启动不会重复迁移。原计算公式不变，只在章节内作差。

“新建记录”中先选择章节和阶段，再粘贴结构化文本，点击“解析并填充表单”。新题示例：

```text
[POLITICS]
stage=A0
chapter=马原
single_completed=68
multiple_completed=58
wrong_single=18
wrong_multiple=32
```

错题复刷示例：

```text
[POLITICS]
stage=A1
chapter=马原
wrong_single=7
wrong_multiple=30
rewrong_single=3
rewrong_multiple=0
```

`single_completed` / `multiple_completed` 是本章节当前累计完成数，导入后会切换为“当前累计”模式。`wrong_single` / `wrong_multiple` 是本章节刷后的 App 错题本余额；`rewrong_single` / `rewrong_multiple` 是本轮再错数。B0/B1/B2 使用相同字段；AX/BX 只需要刷后余额。

对应中文字段支持：`阶段`、`章节`、`单选累计完成数`、`多选累计完成数`、`单选错题数`、`多选错题数`、`单选再错数`、`多选再错数`，同样使用 `字段=值`。空行允许；重复字段、未知字段、负数、缺少必填字段会拒绝解析。一次只导入一个 `[POLITICS]` 块。

解析不会写数据库。章节或阶段与下拉菜单不一致时会提示冲突，保留当前选择和表单；请手动调整选择后重新解析。查看“本轮预览”后点击“确认保存”才创建 Session。

概览支持“全部 / 马原 / 毛中特 / 新思想 / 史纲 / 思修”筛选。全局累计作答、正确率和完成数均从历史 Session 聚合；当前错题池和余额由各章节合计，不需要 App 全局错题总数。日报逐 Session 展示章节，同时提供全局累计与当天涉及章节的累计统计。

## 文件与恢复

“历史与报表”支持日报、周报、月报和自选时间段报。周报选择周内任一天，按周一至周日统计；月报选择月内任一天，按自然月统计；自选报表分别选择开始、结束日期，包含起止两天。没有记录的时间段也能生成报表。

报表将期间作答量和正确率与截至期末的累计统计分开展示，并保留逐条记录、章节累计、题库进度、错题池、备注和数据一致性检查。正确率按总正确数 / 总作答数计算；AX/BX 不计入六轨统计。历史导入仍按存档日期归入报表，并标注实际刷题日期未知。未结束的周/月仅汇总已录入的数据。

所有报表均支持 Markdown、JSON 下载。保存、撤销或重新计算记录时，日报、周报、月报自动更新；自选时间段可点击“保存此时间段报表到本地”，已保存的范围也会随记录更新。

- `data/politics.db`：原始事件和当前派生表。
- `reports/daily/YYYY-MM-DD.md` 和 `.json`：当天日报；JSON 含截至该日的原始事件。
- `reports/weekly/开始日期_结束日期.md` 和 `.json`：有记录的自然周周报。
- `reports/monthly/开始日期_结束日期.md` 和 `.json`：有记录的自然月月报。
- `reports/custom/开始日期_结束日期.md` 和 `.json`：保存的自选时间段报表。非日报 JSON 含期间记录、期间统计、期末累计快照和截至期末的原始事件。
- `reports/snapshots/`：二刷开始时的一刷快照。
- `attachments/`：可选截图。
- `backups/`：启动时每天至多一次自动备份，保留最近 30 个每日备份；也可手动备份。

“重新计算全部统计”从 `events` 重新生成 Session、错题池和当前状态。“撤销最近一次操作”删除最后一条事件并重建。界面可导出 Session CSV、Session JSON、当前统计 Markdown 和完整 SQLite 数据库。要跨电脑迁移，优先复制完整 SQLite 数据库及需要保留的截图附件。

数据库、报表、截图、备份、日志和虚拟环境均已被 Git 忽略，不会上传到远程仓库。克隆仓库只会取得应用代码；个人学习数据需要另外迁移。
